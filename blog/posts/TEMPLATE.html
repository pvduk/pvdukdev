Clean Architecture e Web Standards: Construindo Software Resiliente Sem Dependências

Por que frameworks são apenas detalhes de entrega e como aplicar os princípios de Uncle Bob na plataforma nativa para ter 100 de Lighthouse sem carregar 50MB de dependências.

15 de Janeiro de 2025 8 min de leitura
  • #arquitetura

Paulo Dukven Engenheiro de Software e FullStack C#/React

Se você precisa baixar 800MB de dependências para centralizar uma div e disparar uma requisição assíncrona, a sua arquitetura tem um problema sério.

Alguns anos atrás, vi um pipeline de CI travar por 25 minutos porque um pacote transitório de formatação de string quebrou uma compilação na sexta-feira à tarde. Uma linha de código utilitária que qualquer desenvolvedor escreveria em dois minutos arrastou catorze serviços para o chão.

Esse é o custo real da dependência cega: você troca o domínio do seu produto pelos caprichos de ecossistemas instáveis.

Princípio Fundamental da Arquitetura Limpa

"A arquitetura não deve ser sobre frameworks. Frameworks são opções de entrega, não o coração do seu sistema." — Robert C. Martin (Uncle Bob)

O erro de confundir ferramenta com arquitetura

Quando Uncle Bob formalizou a Clean Architecture, a premissa era direta: as regras de negócio vivem no centro; o banco de dados, a rede e a interface gráfica são meros detalhes de borda.

No frontend, o mercado inverteu essa lógica. Criou-se o hábito perigoso de acoplar o modelo de domínio aos hooks de uma biblioteca específica ou à sintaxe proprietária do bundler da moda. Quando a ferramenta decide lançar uma versão com quebra de contrato, o software inteiro envelhece da noite para o dia.

Contratos limpos na web nativa

A plataforma web moderna (HTML5 semântico, CSS Cascade Layers e ES2026 modular) já resolve a imensa maioria dos desafios que antes justificavam pilhas colossais de bibliotecas.

Separar responsabilidades de verdade não exige dependências pesadas de terceiros: 

// Contrato explícito: o modelo de dados não conhece quem o consome
export async function loadPostManifest(fetcher = fetch) {
  const response = await fetcher('../data/posts.json');
  if (!response.ok) {
    throw new Error(`Falha ao carregar manifesto: HTTP ${response.status}`);
  }
  return await response.json();
}

Ao injetar o fetcher e isolar o contrato de dados em um manifesto puro, a interface fica 100% desacoplada de detalhes de rede. Testar essa rotina no Node.js leva 3 milissegundos: sem mock complexo, sem jsdom e sem emulador de navegador.

Menos camadas, mais controle

Adotar os padrões nativos da web não é preciosismo. É respeito à bateria, à memória RAM e à conexão do usuário.

Quando você remove as camadas artificiais, o resultado é direto: zero latência, carregamento instantâneo e um sistema que continua funcionando daqui a dez anos sem quebrar a cada atualização de dependências.
